# FuckBot SNO — робот на танковой схеме

Прошивка и документация для колёсного робота: **Arduino Uno + HC-06 (Bluetooth) + L298N (два моста)**.
Управление — с Android-джойстика: по Bluetooth приходят **два числа от −100 до 100**
(вперёд/назад и вправо/влево), прошивка сама пересчитывает их в скорости бортов.

```
FuckBot_SNO/
├── firmware/FuckBot_SNO/FuckBot_SNO.ino   ← прошивка (открывать в Arduino IDE)
├── tools/bt_check.py                      ← проверка робота с ПК по BT (pyserial)
└── test/                                  ← тесты логики на ПК (эмулятор Arduino API)
    ├── main.cpp
    ├── mock/Arduino.h
    └── Makefile
```

## 1. Схема подключения

### L298N → Arduino

| L298N | Arduino | Что это |
|-------|---------|---------|
| ENA   | D5      | ШИМ скорости **левого** борта (обязательно PWM-пин: 3, 5, 6, 9, 10, 11) |
| IN1   | D7      | направление левого |
| IN2   | D8      | направление левого |
| ENB   | D6      | ШИМ скорости **правого** борта |
| IN3   | D9      | направление правого |
| IN4   | D10     | направление правого |
| GND   | GND     | **общая земля — без неё ничего не работает** |
| OUT1/OUT2 | —   | левый мотор |
| OUT3/OUT4 | —   | правый мотор |
| +12V / VCC | —   | плюс батареи (7,4–12 В), моторы питаются отсюда |

Пины меняются в блоке «Пины Arduino» в начале `.ino`.

### HC-06 → Arduino

| HC-06 | Arduino |
|-------|---------|
| VCC   | 5V      |
| GND   | GND     |
| TXD   | D0 (RX) |
| RXD   | D1 (TX) — правильнее через делитель 1 кОм / 2 кОм, т.к. вход модуля 3,3 В |

⚠️ **Перед прошивкой по USB отключите провода D0/D1 от HC-06**, иначе модуль будет мешать
загрузке скетча (и получит чужой UART-трафик).

### Питание

- Моторы — **только** от батареи через L298N. Никогда не питайте моторы от 5 В Arduino.
- Земли Arduino, L298N и батареи соединяются вместе.
- Джампер `5V_EN` на L298N: если он стоит, модуль сам выдаёт 5 В на Arduino — но только
  при питании до ~12 В. При 3S-батарее (11,1–12,6 В) джампер лучше снять и питать
  Arduino отдельно (USB-павербанк / DC-DC).
- Электролит 220–1000 мкФ параллельно питанию L298N заметно уменьшает просадки и
  перезагрузки Arduino при старте моторов.

## 2. Протокол

Текст, ASCII, **9600 8N1** (заводские настройки HC-06). Кадр:

```
<Y>,<X>\n
```

| Поле | Диапазон | Смысл |
|------|----------|-------|
| Y | −100…100 | + вперёд, − назад |
| X | −100…100 | + вправо, − влево |

Примеры:

| Кадр | Действие |
|------|----------|
| `0,0\n` | стоп |
| `100,0\n` | полный вперёд |
| `-60,0\n` | назад на 60 % |
| `0,100\n` | разворот вправо на месте |
| `60,40\n` | дуга вправо на ходу (борта 100 % и 20 %) |
| `0,-70\n` | разворот влево на месте |

Правила разбора (реализованы в `parseFrame()`):

- разделитель между числами — **любой** нецифровой символ: `,` `;` `:` пробел `=` …
  Поэтому подойдут и `40;10`, и `40 10`, и `y=40,x=10`;
- конец кадра — `\n` или `\r`. **Перевод строки обязателен**, иначе `100100` склеится;
- если пришло одно число — это Y, X считается нулём;
- значения вне диапазона обрезаются до ±100;
- мусорная строка (без чисел) просто игнорируется — последняя команда продолжает действовать;
- `y`/`x` меньше 4 % считаются нулём (мёртвая зона стика, убирает дрожание).

### Что происходит внутри

1. Приём кадров — неблокирующий, буфер 32 байта, переполнение отбрасывается.
2. Микшер танковой схемы: `левый = Y + X`, `правый = Y − X`, затем нормализация —
   если при повороте на полном ходу борт выходит за 100 %, оба борта масштабируются
   пропорционально, чтобы робот не терял скорость на дуге.
3. Плавный разгон (`ACCEL_PCT_PER_S`) — рывки рвут пластиковые редукторы и просаживают батарею.
4. `MIN_PWM` (30) — ниже этого ШИМ моторы не крутятся, а только гудят и греются,
   поэтому скорость 1 % выдаётся как ШИМ 30, а 100 % — как 255.
5. **Failsafe**: нет корректных кадров 600 мс → моторы мгновенно обесточиваются
   (телефон уснул, приложение свернулось, связь пропала).

## 3. Прошивка

1. Arduino IDE → **File → Open** → `firmware/FuckBot_SNO/FuckBot_SNO.ino`
   (папка со скетчем должна называться так же, как файл).
2. Плата: **Arduino Uno**, порт — ваш COM-порт.
3. Отключите D0/D1 от HC-06, нажмите **Upload**, верните провода.

### Настройки (начало `.ino`)

| Параметр | По умолчанию | Зачем менять |
|----------|--------------|--------------|
| `SERIAL_BAUD` | 9600 | если HC-06 перепрошит на другую скорость |
| `FAILSAFE_MS` | 600 | `0` — отключить. **Нужно**, если приложение шлёт кадры только при движении стика |
| `MIN_PWM` | 30 | мотор гудит, но не едет → увеличьте до 40–60 |
| `MAX_PWM` | 255 | ограничение скорости для ребёнка/тонкого пола, напр. 180 |
| `SPEED_LIMIT` | 100 | общий потолок скорости, % |
| `ACCEL_PCT_PER_S` | 700 | `0` — резкий старт; 300 — совсем плавно |
| `INPUT_DEADBAND` | 4 | увеличить, если робот «ползёт» при отпущенном стике |
| `NORMALIZE_MIX` | true | `false` — поворот «съедает» скорость |
| `BRAKE_ON_STOP` | false | `true` — тормозить двигателями вместо наката |
| `INVERT_Y` / `INVERT_X` | false | приложение прислало обратные знаки |
| `INVERT_LEFT` / `INVERT_RIGHT` | false | один борт крутится не в ту сторону |
| `SWAP_SIDES` | false | робот крутится на месте вместо езды прямо (перепутаны моторы) |

Проверка «на весу» (колёса в воздухе): подайте `100,0` — оба колеса должны крутиться
вперёд; `0,100` — левое вперёд, правое назад.

## 4. Android-приложение

HC-06 — это **Bluetooth Classic (SPP)**, не BLE. В приложении нужен `BluetoothSocket`
с UUID `00001101-0000-1000-8000-00805F9B34FB`. PIN при спаривании — `1234` или `0000`.

### Вариант А — готовое приложение

Любое приложение с джойстиком, которое умеет отправлять **свой текстовый формат** кадра
(в них это обычно называется custom/advanced mode). Настройте формат на
`<Y>,<X>\n` с диапазоном −100…100. Для отладки удобен «Serial Bluetooth Terminal»:
наберите `50,0` и нажмите отправку с переводом строки.

Если приложение шлёт что-то другое (`F/B/L/R`, `1,2,3…`, HEX-байты) — проще
подстроить `parseFrame()` под него, чем искать «правильное» приложение.

### Вариант Б — своё приложение (Kotlin, ~40 строк)

```kotlin
private const val SPP_UUID = "00001101-0000-1000-8000-00805F9B34FB"

class RobotLink(private val device: BluetoothDevice) {
    private var socket: BluetoothSocket? = null
    private var out: OutputStream? = null

    fun connect() {
        val s = device.createRfcommSocketToServiceRecord(UUID.fromString(SPP_UUID))
        s.connect()                       // в фоновом потоке, не в UI!
        socket = s
        out = s.outputStream
    }

    fun send(y: Int, x: Int) {
        val o = out ?: return
        o.write("${y.coerceIn(-100, 100)},${x.coerceIn(-100, 100)}\n"
            .toByteArray(Charsets.US_ASCII))
    }

    fun close() {
        send(0, 0)                        // стоп перед закрытием
        runCatching { socket?.close() }
    }
}
```

Отправка из значения стика (20–50 Гц, это же и держит failsafe живым):

```kotlin
// stickX/stickY: -1f..1f из onTouchEvent (вверх по экрану = вперёд)
fun pushStick(stickY: Float, stickX: Float) {
    scope.launch {
        while (isActive) {
            link.send((stickY * 100).toInt(), (stickX * 100).toInt())
            delay(20)
        }
    }
}
```

Важно:

- разрешения: Android 12+ — `BLUETOOTH_CONNECT` (+`BLUETOOTH_SCAN` для поиска),
  ниже — `BLUETOOTH`, `BLUETOOTH_ADMIN`;
- `connect()`, `write()` — всегда вне главного потока (иначе `NetworkOnMainThreadException`);
- в `onPause()`/`onDestroy()` — отправить `0,0` и закрыть сокет.

## 5. Проверка без телефона

**Логика на ПК** (эмулятор Arduino API, никакого железа не нужно):

```bash
make -C test        # 48 проверок: микшер, разбор кадров, failsafe, разгон, реверс
```

**Робот с ПК по Bluetooth** (нужен `pip install pyserial` и спаренный HC-06 как COM-порт
или `/dev/rfcomm0`):

```bash
python3 tools/bt_check.py COM5            # стрелки/WASD, живой джойстик
python3 tools/bt_check.py COM5 --demo     # автопрогон всех режимов
```

## 6. Если что-то не так

| Симптом | Причина / решение |
|---------|-------------------|
| Моторы молчат, LED не горит | кадры не доходят: проверьте, что приложение шлёт `\n`, и скорость 9600 |
| LED горит, колёса стоят | `MIN_PWM` слишком мал — поднимите до 40–60 |
| Едет, но дёргается | приложение шлёт только при изменении стика → `FAILSAFE_MS = 0` |
| Крутится на месте вместо «прямо» | `SWAP_SIDES = true`, либо моторы подключены крест-накрест |
| Один борт едет назад | `INVERT_LEFT` / `INVERT_RIGHT` |
| Arduino перезагружается при старте моторов | общая земля, конденсатор на питание L298N, отдельное питание Arduino |
| Ничего не грузится по USB | отключите D0/D1 от HC-06 на время прошивки |
| Робот не реагирует после пары секунд | сработал failsafe (600 мс без кадров) — проверьте частоту отправки |
