# FuckBot RC — Android-приложение с джойстиком

Пульт для робота из этого репозитория: экранный джойстик, кнопка СТОП, ограничение
скорости и подключение к HC-06 по **Bluetooth Classic (SPP)**.

- Kotlin, **без единой внешней зависимости** (только Android SDK) — сборка не тянет
  ничего лишнего из сети, приложение весит копейки;
- `minSdk 24`, `targetSdk 34`;
- кадры уходят 50 раз в секунду (`20 мс`), поэтому failsafe в прошивке всегда сыт.

---

## Как собрать

1. Android Studio → **Open** → выберите каталог `android/`.
2. Дождитесь Gradle Sync (Studio сама скачает Gradle 8.7 по `gradle-wrapper.properties`;
   JDK 17 входит в комплект Studio).
3. Подключите телефон по USB (включён режим разработчика + отладка по USB) и нажмите **Run**.

Сборка APK без Studio (если установлен Gradle 8.7+):

```bash
cd android
gradle wrapper          # один раз, создаст gradlew и gradle-wrapper.jar
./gradlew assembleDebug # APK: app/build/outputs/apk/debug/app-debug.apk
```

> В репозитории лежат `gradle-wrapper.properties`, но без бинарного `gradle-wrapper.jar`
> (его не кладут в git-артефакты сборки). Android Studio sync'ится и без него,
> а для консоли достаточно один раз выполнить `gradle wrapper`.

## Как подключиться к роботу

1. Включите питание робота (HC-06 замигает).
2. **Настройки Bluetooth телефона → спарить HC-06** (PIN `1234` или `0000`).
   Приложение само не спаривает — оно работает со списком уже спаренных устройств.
3. Откройте FuckBot RC → **Подключить** → выберите HC-06 из списка.
4. Индикатор в шапке станет зелёным — можно ехать.

На Android 12+ приложение попросит разрешение «Устройства поблизости» — без него
подключение невозможно (это `BLUETOOTH_CONNECT`).

## Что на экране

| Элемент | Назначение |
|---------|-----------|
| Кружок слева вверху | Состояние связи: серый — нет, жёлтый — подключение, зелёный — связь есть, красный — ошибка |
| Кнопка «Подключить / Отключить» | Открывает список спаренных устройств |
| Джойстик | Вверх/вниз — вперёд/назад, влево/вправо — поворот. Отпустили — робот встал |
| `Y … X …` | Тот самый кадр, который уходит в UART (удобно для отладки) |
| Ползунок «Скорость» | Ограничение максимальной скорости (10…100 %) |
| СТОП | Мгновенный сброс стика в центр и нулевая команда |

При сворачивании приложения или выключении экрана канал закрывается, робот получает
`0,0` и встаёт. Экран во время езды не гаснет (`FLAG_KEEP_SCREEN_ON`).

## Как это устроено

```
MainActivity.kt   — экран, разрешения, выбор устройства, индикация
JoystickView.kt   — кастомный View: круглая база, ручка, возврат в центр
BtLink.kt         — сокет SPP + поток отправки 50 Гц + «стоп» при разрыве
Protocol.kt       — формат кадра и перевод стика в проценты (без Android API)
```

Поток данных: палец → `JoystickView` отдаёт `x, y` в `-1..1` → `Protocol.stickToPercent()`
(с мёртвой зоной 5 %) → умножение на ползунок скорости → `BtLink.setCommand()` →
рабочий поток пишет `"Y,X\n"` в сокет каждые 20 мс → HC-06 → Arduino.

Если писать в сокет не удалось (робот уехал из зоны, сел аккумулятор модуля),
приходит `IOException` — приложение показывает «Связь потеряна» и закрывает канал.

### Хочу другой формат кадра

Всё в одном месте — `Protocol.frame()`:

```kotlin
return String.format(Locale.US, "%d,%d\n", y, x).toByteArray(Charsets.US_ASCII)
```

Например, для прошивки на одиночных буквах: `if (y > 0) "F" else if (y < 0) "B" …`.

### Стик едет наоборот

Джойстик отдаёт «вверх = +Y». Если хочется инверсию, поменяйте знак в
`JoystickView.notifyMove()` или в `MainActivity.onMove()` — но правильнее инвертировать
один раз на стороне прошивки (`INVERT_Y` / `INVERT_X` в `.ino`).

## Частые проблемы

| Симптом | Решение |
|---------|---------|
| В списке нет HC-06 | Модуль не спарен. Спарьте его в системных настройках Bluetooth, затем снова «Подключить» |
| «Не удалось подключиться к HC-06» | Канал занят: HC-06 держит **одно** подключение. Закройте другие терминалы/приложения, выключите и включите робота |
| «Нет разрешения на Bluetooth» | Отклонили разрешение при первом запуске: Настройки → Приложения → FuckBot RC → Разрешения → «Устройства поблизости» |
| Робот дёргается | Ползунок скорости на минимуме? Проверьте `MIN_PWM` в прошивке — при слишком малом значении моторы гудят |
| Робот едет рывками на ровном месте | Мёртвая зона в приложении (5 %) и `INPUT_DEADBAND` в прошивке (4 %) — увеличьте одну из них |
| Есть задержка ~0.5 с | Признак перегруженного канала: 50 кадров/с по 6 байт — это норма. Если телефон в режиме энергосбережения, поток может тормозиться |
| Приложение закрылось при повороте экрана | Не должно: `configChanges` в манифесте сохраняет активити и соединение. Если повторится — пришлите лог |

## Проверка

Код проверялся компилятором Kotlin (2.4.21) против заглушек Android API — синтаксические
и типовые ошибки исключены; логика `Protocol` (18 проверок: мёртвая зона, обрезка
диапазона, ASCII-кадры) прогнана отдельным тестом на JVM.

Окончательная проверка «в бою» — сборка в Android Studio и поездка по квартире.
